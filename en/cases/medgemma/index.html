MedGemma Lung LoRA

Fine-tuning a medical AI model to estimate the lung-to-thorax ratio on chest X-rays. A personal study project.

Limits, first. 1.98% mean error in validation against the segmentation masks of a public dataset. Qualitative test on 4 external images, without ground truth. No clinical validation. It does not diagnose anything.

Case card

Context
A personal study project, driven by a practical skill gap I wanted to close: fine-tuning a medical vision model from scratch.
My role
Solo, from start to finish. The technical and product decisions (what to train, which metric to use, when to change approach) were mine. I used Claude Code as a programming partner for execution; the clinical reading, the problem definition and the judgment on how reliable the result was were mine.
Skills this case shows
Framing a testable hypothesis before training; spotting data and metric bias before it becomes a silent error; validating against external cases instead of trusting only the training metric; justifying a technical trade-off with clinical reasoning; documenting limits in proportion to the result.
Tools
MedGemma (Google), Hugging Face (transformers, peft), LoRA, Gradio, scikit-image, local NVIDIA GPU · AI-assisted programming
Evidence
Public repository on GitHub, with code, a README of the process and images of the app

Problem

This project did not come from a clinical problem reported by a real user, nor from validated market demand. It came from a practical skill gap (I did not know, in practice, how to fine-tune a medical vision model) and from a hypothetical clinical question: can a useful measure be extracted from a chest X-ray, automatically and quantitatively, instead of only a qualitative description ("small", "moderate", "large")?

Quantitative radiology already uses geometric measures for similar findings, such as the cardiothoracic ratio and Light's index for pneumothorax. That makes the question clinically plausible, even without a user waiting for the answer today.

Hypothesis

If I trained a model on top of MedGemma's vision encoder to predict the lung-to-thorax ratio, I expected it to generalize reasonably to images outside the training set, because the architecture is already pre-trained on medical images.

  • Primary metric: mean absolute error (MAE) in validation, against the label computed from the dataset's segmentation mask (not against specialist reading).
  • Success criterion, formalized along the way rather than set in advance: low validation error and directional coherence in at least one external test with a known clinical expectation (the inspiration/expiration pair of the same patient).
  • Cheaper hypothesis, tested first: a linear probe (one layer trained on top of the frozen encoder) would be enough. It worked only in part: the encoder carries enough signal, but the probe did not generalize to cases outside the training set.

Investigation

  1. Dataset: Montgomery + Shenzhen Chest X-ray Segmentation (Mendeley Data, CC BY 4.0, DOI 10.17632/8gf9vpkhgy.2), 704 X-rays with lung masks annotated by specialists, built for tuberculosis screening.
  2. Thorax mask: the dataset only had lung masks; I computed the thorax mask with an intensity threshold.
  3. Error one, automatic threshold: on some images, Otsu's method split "dark lung" from "bright bone" instead of "background" from "body" and broke the thorax apart. Fixed with a low, fixed threshold.
  4. Error two, framing: the first label was lung ÷ whole image. On a more tightly cropped external image, the value jumped: framing, not physiology, drove the number. Fixed to lung ÷ thorax.
  5. Linear probe: frozen encoder, one new layer. About 2.4% validation MAE, but it barely caught the inspiration/expiration difference (0.2 point) and had a post-surgery case far off the curve (39.4%).
  6. LoRA fine-tuning: last 6 of 27 attention layers, trained with the regression head. MAE dropped from 4.59% at epoch 1 to 1.98% at epoch 8, with no sign of overfitting.
  7. Retest on the 4 external images: the inspiration/expiration difference rose to 1.9 points (clinically correct direction) and the post-surgery case fell from 39.4% to 30.6%, with no ground truth to confirm the right value.

Limit of the investigation. Validation was always against the dataset's own ground truth, never against an independent second source. The external sample (4 images) is too small for any statistical conclusion: it is a sanity check, not validation.

Solution

  • Proposal: a pipeline that takes a chest X-ray and returns one number, the fraction of the thorax taken up by the lungs.
  • Flow: image → MedGemma vision encoder (with the LoRA adapter) → regression head → number, in a simple web interface (Gradio).
  • User: hypothetical, never tested with a real user. A physician or researcher exploring an auxiliary signal, never as a diagnostic reading.
  • What it does not do: it does not measure volume in liters or area in cm² (the images have no physical scale); it does not separate the two lungs; it does not diagnose any condition.
  • What it would take to go beyond a study: a dataset with real clinical labels, prospective validation against specialist reading and, most likely, regulatory approval.

Risks

  • Clinical: the number being read as a validated clinical measure. Mitigated with a warning in the interface and a limitations section in the README.
  • Data: no identifiable patient data. The dataset is public and anonymized; the 4 external images came from public educational material, not from medical records.
  • Bias: the dataset comes from two tuberculosis screening programs (USA and China), with specific populations, machines and framing. The reference mask under-marks the costophrenic angle, and the model inherits that bias.
  • Operational: MedGemma has a restricted-use license (terms acceptance on Hugging Face), and reproducing the project requires a CUDA GPU.

Impact

The baseline was no automatic signal extracted from the image. The result: 1.98% mean error in validation against the dataset ground truth, and better generalization on external images after LoRA (inspiration/expiration difference from 0.2 to 1.9 points; post-surgery case from 39.4% to 30.6%).

There is no clinical or product impact, and that is stated here on purpose. The value is the skill: taking a health ML project from zero to a measurable result, with clinical judgment in every method decision.

The core lesson: a good validation result on your own dataset does not prove generalization. The external images exposed the real problems, and fixing them is what moved the project forward.

If the project continued, the README describes possible directions (an inspiration/expiration stiffness marker for COPD, an automated cardiothoracic ratio, follow-up of congestion in heart failure). All would need a dataset with real clinical labels before any use beyond study.
