Medical Prescription Assistant

A web app I built for a pain point in my own work: turning prescription writing into selecting and clicking.

Limits, first. An individual support tool, built for my own workflow, not a product for other services. It does not suggest doses or treatment decisions: it only formats the prescription the physician has already decided. The time saved is my estimate, not a measurement.

Case card

Context
A personal project. It came from a recurring pain point in my work: prescriptions were written by hand, with no digital standard.
My role
Solo, from scope to architecture. I defined the protocols and pre-set templates, decided to replace writing with selecting and designed the AI sub-agent architecture used to build the project. I used AI as a development partner for technical execution; the product and clinical workflow decisions were mine.
Skills this case shows
Defining product scope from a pain point lived in clinical practice; choosing between personalizing and generalizing a system; using a multi-agent AI setup to build software as a physician, not an engineer.
Tools
Next.js with static export, TypeScript, Cloud Firestore, Firebase Authentication and Firebase Hosting (Google Cloud, serverless), AI sub-agents (Claude Code)

Problem

In my work, each handwritten prescription took about 10 minutes, even when much of the content repeated from one patient to the next. The process ran on paper and spreadsheets, with no digital standard. It was a lot of time for a repetitive task.

What I did

  • Personal scope: I chose to build a system for my own workflow, not a generic system for any service. It comes set up with the medications and prescriptions I use most.
  • Templates and protocols: I pre-set recurring clinical templates and protocols, such as insulin therapy and hypertensive emergency, to cut repetitive typing.
  • Core design decision: I replaced writing with clicking and selecting in tables. The bet: repeated typing is what eats the time.
  • Deliberate scope limit: the system only structures and formats the prescription I have already decided. No AI model suggests doses or treatment. The clinical decision stays entirely mine.
  • Sub-agent architecture: I built the project with a coordinator agent that calls specialized sub-agents (backend, frontend, database and code review), in a design I defined.
  • Confidentiality: the code is white-label. No institution name or logo is kept in the code.

Result

I designed, built, prototyped and tested the workflow in my own use. By my estimate, the time per prescription dropped from about 10 minutes to 3 to 5 minutes.

The main gain is not speed itself. It is less time on paperwork and more time to analyze, discuss and pay attention to patients.
